# CR-0018: Mechanical enforcement of PA-0027 (broad exception handlers fail closed)

**Status: DRAFT (v2), 2026-09-30, for re-review.** Verdicts and
dispositions: `CR-0018-review-log.md`. This document states only current
intent.

## Scope
Add `tests/test_pa0027_lint.py`, a unittest-based AST lint over the
tracked `*.py` file set that fails on any broad exception handler that
does not re-raise and is not on a reviewed, digest-pinned classification
list. No production code changes.

## Why now
- PA-0027 (supersedes PA-0011, from BUG-0049) says "Enforcement: review
  only until a lint test exists (tracker; needs a CR)". The tracker item
  is `docs/quality/CR-0007-0008-OPEN-ISSUES.md` § "PA-0027 enforcement",
  owner lead.
- Review-only enforcement already failed once for this mechanism:
  BUG-0049 is a recurrence of BUG-0013, and its §7 names "Not enforced"
  as one of the reasons PA-0011 did not prevent it.
- CLAUDE.md §3.4: mechanical enforcement where feasible. An AST check is
  feasible here and cheap (whole run about 1 s).
- Precedent: `tests/test_nodata_zero_lint.py` (CR-0015, PA-0006) and
  `tests/test_shared_constants.py` (CR-0007, PA-0025).

## The change

### 1. File set
`git ls-files '*.py'` minus `inv_*`, `res_*` and `docs/**` — the same
set as `tests/test_nodata_zero_lint.py`, `tests/` included. Files whose
first statement after the docstring is `raise SystemExit(...)`
(`check_partition.guard_first`, PA-0026) cannot run and are not scanned;
that set is pinned (`EXPECTED_GUARDED`: `clean.py` and the seven
`legacy/*.py`), so a new guarded file, or a guard removed, fails the test.

### 2. Lint rule
- **Broad** (PA-0027's list): bare `except:`; a handler type naming
  `Exception` or `BaseException` (as a name or an attribute such as
  `builtins.Exception`); a tuple containing one of those; `except*`
  handlers of the same types. Also a call `suppress(<broad type>)`
  (`contextlib.suppress`), which is `except Exception: pass`.
- **Conforms mechanically** iff every path through the handler body ends
  the operation abnormally. The body's statements are taken in order:
  - the first statement that **can leave the handler normally** makes
    the handler non-conforming: it contains a `return` anywhere, or a
    `break`/`continue` that is not inside a loop nested within it
    (nested `def`/`class`/`lambda` ignored; `finally` blocks included);
  - otherwise the first statement that **always aborts** makes it
    conform. Always aborts:
    - `raise` — for `SystemExit`, only with a non-falsy constant or an
      f-string argument (so not bare `SystemExit`, `SystemExit()`,
      `SystemExit(0/None/False)` or `SystemExit(var)`);
    - an expression statement calling `sys.exit`, `os._exit`, `exit` or
      `quit` with such an argument;
    - an `if` whose body and `else` both always abort;
    - a `with` whose body always aborts, unless an item is a
      `suppress(...)` call;
    - a `try` whose `finally` always aborts, or whose body (with `else`)
      and every handler always abort.
  - Falling off the end (e.g. `pass`, a log line, a conditional raise
    without an `else`) does not conform. `suppress(<broad>)` never does.
- **Classified by review** otherwise. Key:
  `(path, enclosing qualname, ordinal of the broad handler in that scope)`,
  never a line number. Each entry pins a 12-hex digest of the handler's
  AST **and of its whole enclosing scope** (innermost `def`/`class`, or
  the module-level statement; `ast.dump` without positions, 3.12-format
  output also on 3.13+). A classified handler's meaning can depend on
  code after it in the same function (a fallback, a final check), so an
  edit anywhere in that function fails the test until re-reviewed.

### 3. Classified sets (in the test; disjoint)
| set | meaning | entries today |
|---|---|---|
| `ALLOWLIST` | conforms by PA-0027's fail-closed / visible-unknown / cleanup / fallback clauses; each entry has a class and a reason citing the PA-0027 sweep (BUG-0049 §8) line it came from. A visible-unknown entry must print or record the exception type (PA-0027's text) | 17 |
| `KNOWN_OPEN` | known defect with an owning open BUG | 3 (BUG-0013) |
| `EXPECTED_UNCLASSIFIED` | CR-0018's BUG candidates (§4), pinned until each is filed and either fixed or moved to `ALLOWLIST` by its own review | 16 (C1–C7) |

The repository test passes iff the set of non-conforming broad handlers
equals the union of the three sets exactly, with every digest equal. So
it fails on: a new non-conforming handler; an edit to a classified
handler or its enclosing function; a stale entry left behind by a fix
(the fix must remove it). When a new and a changed handler share a
scope, the failure output adds a hint that an inserted handler may have
shifted the ordinals.

The allowlist carries over the PA-0027 sweep's classification, re-located
after `4683e3c` shifted line numbers, minus every entry that review
round 1 found does not meet PA-0027's text (moved to §4). The full
listing (path, current line, key, digest, set) is
`docs/quality/evidence/CR-0018/lint-run.txt`.

### 5. Known limits (not detected; recorded, not in scope)
- A broad type reached through an alias (`E = Exception; except E:`,
  `except (E := Exception)`) or an aliased `suppress` import. None today:
  every handler type expression in the 61 scanned files was listed from
  the AST; apart from `Exception`/`BaseException` each is a builtin
  narrow type, a library type, or a project subclass of `Exception`
  (`AcceptanceError`, `ConfigError`, `GuardError`, `Missing`,
  `MissingDataError`, `MissingInput`, `ReplayError`). No `suppress(` call
  exists in the file set.
- Laundering: a broad handler that re-raises a narrow exception which an
  enclosing narrow handler in the same function catches and skips
  (`except Exception as e: raise Skip() from e` … `except Skip: continue`).
- Narrow handlers that skip (`except OSError: continue`). PA-0027 is
  about broad handlers; narrow skips are governed by its "printed with
  what was skipped" clause, which is not mechanically checkable.
- Whether a *caller* in another function treats a handler's fail-closed
  value correctly (e.g. a probe's `False` read as "skip"; a
  nearest-year fallback). The digest pins the handler's own function,
  not its callers. Review only.
- Whether a visible-unknown message includes the exception type: judged
  by review when an entry is classified, not checked mechanically.
- `return`/`break`/`continue` in a `finally` of the *protected* `try`
  (swallows an in-flight exception without any handler). Not in
  PA-0027's text; tracked as a follow-up question.
- Acceptance scripts under `docs/quality/evidence/` are excluded, as in
  the precedent lint; none has a broad handler today.

## Impact
- Test-only. No production file, data file or schema changes. Nothing
  writes to `data/`.
- Any future change adding a broad handler that does not re-raise, or
  editing a function that holds a classified one, now fails `python -m
  unittest tests.test_pa0027_lint` and must add or update an entry,
  which is a review item. That is the intended friction; digests of
  large functions (e.g. `acceptance_split.full_run`) will churn with
  unrelated edits there.
- Imports `check_partition.guard_first` (numpy/pandas import, ~0.3 s),
  as `tests/test_shared_constants.py` already does.

## Risk
LOW. Test-only change. Failure modes and mitigations:
- *False assurance*: an allowlist entry wrongly classifies a real defect
  as conforming. Mitigation: every entry is carried over from the PA-0027
  sweep with its sweep line cited, and both reviewers re-derived the
  classifications from the code (T8); entries they disputed are in §4.
- *Rule too narrow*: a defect shape the AST rule accepts (§5). Accepted
  risk, listed.
- *Churn*: digest pins fail on harmless edits to a function holding a
  classified handler. Accepted: re-review is the point of the PA.
