# CR-0018: Mechanical enforcement of PA-0027 (broad exception handlers fail closed)

**Status: DRAFT (v1), 2026-09-30, for review.** Verdicts and dispositions:
`CR-0018-review-log.md`. This document states only current intent.

## Scope
Add `tests/test_pa0027_lint.py`, a unittest-based AST lint over the
tracked `*.py` file set that fails on any broad exception handler that
does not re-raise and is not on a reviewed, digest-pinned classification
list. No production code changes.

## Why now
- PA-0027 (supersedes PA-0011, from BUG-0049) says "Enforcement: review
  only until a lint test exists (tracker; needs a CR)". The tracker item
  is `docs/quality/CR-0007-0008-OPEN-ISSUES.md` § "PA-0027 enforcement",
  owner lead.
- Review-only enforcement already failed once for this mechanism:
  BUG-0049 is a recurrence of BUG-0013, and its §7 names "Not enforced"
  as one of the reasons PA-0011 did not prevent it.
- CLAUDE.md §3.4: mechanical enforcement where feasible. An AST check is
  feasible here and cheap (whole run under 1 s).
- Precedent: `tests/test_nodata_zero_lint.py` (CR-0015, PA-0006) and
  `tests/test_shared_constants.py` (CR-0007, PA-0025).

## The change

### 1. File set
`git ls-files '*.py'` minus `inv_*`, `res_*` and `docs/**` — the same
set as `tests/test_nodata_zero_lint.py`, `tests/` included. Files whose
first statement after the docstring is `raise SystemExit(...)`
(`check_partition.guard_first`, PA-0026) cannot run and are not scanned;
that set is pinned (`EXPECTED_GUARDED`: `clean.py` and the seven
`legacy/*.py`), so a new guarded file, or a guard removed, fails the test.

### 2. Lint rule
- **Broad** (PA-0027's list): bare `except:`; a handler type naming
  `Exception` or `BaseException` (as a name or an attribute such as
  `builtins.Exception`); a tuple containing one of those; `except*`
  handlers of the same types. Also `suppress(<broad type>)`
  (`contextlib.suppress`), which is `except Exception: pass`.
- **Conforms mechanically** iff every path through the handler body
  ends the operation abnormally:
  - a `raise` statement, except `raise SystemExit`, `SystemExit()`,
    `SystemExit(0)`, `SystemExit(None)`, `SystemExit(False)` (exit 0);
  - an expression statement calling `sys.exit`, `os._exit`, `exit` or
    `quit` with an argument that is not absent/0/None/False;
  - an `if` whose body and `else` both conform; a `with` whose body
    conforms; a nested `try` whose `finally` conforms, or whose body and
    every handler conform.
  Everything else — `return`, `continue`, `break`, `pass`, falling off the
  end, a conditional raise with no `else`, a `raise` inside a nested
  `def` — does not conform mechanically. `suppress(<broad>)` never does.
- **Classified by review** otherwise. Key:
  `(path, enclosing qualname, ordinal of the broad handler in that scope)`,
  never a line number. Each entry also pins a 12-hex digest of the
  handler's AST (`ast.dump`, no positions), so an edit to a classified
  handler changes its digest and fails the test until re-reviewed.

### 3. Classified sets (in the test; disjoint)
| set | meaning | entries today |
|---|---|---|
| `ALLOWLIST` | conforms by PA-0027's fail-closed / visible-unknown / cleanup / fallback clauses; each entry has a class and a reason citing the PA-0027 sweep (BUG-0049 §8) line it came from | 30 |
| `KNOWN_OPEN` | known defect with an owning open BUG | 3 (BUG-0013) |
| `EXPECTED_UNCLASSIFIED` | CR-0018's BUG candidates (§4), pinned until each is filed and either fixed or moved to `ALLOWLIST` by its own review | 3 |

The repository test passes iff the set of non-conforming broad handlers
equals the union of the three sets exactly, with every digest equal. So
it fails on: a new non-conforming handler; an edited classified handler;
a stale entry left behind by a fix (the fix must remove it).

The allowlist is the PA-0027 sweep's classification carried over, not a
new judgment: every "fail-closed / abort", "visible unknown", "cleanup"
and "fallback between equals" row of PA-0027's Swept? cell, re-located
after `4683e3c` shifted some line numbers. Its per-entry classes and
reasons are part of what this CR asks reviewers to check. The lint run's
full listing (path, current line, key, digest, set) is
`docs/quality/evidence/CR-0018/lint-run.txt`.

### 4. What the lint flags on today's tree (BUG candidates, not fixed here)
36 non-conforming broad handlers in 61 scanned files; 33 match the PA-0027
sweep's classification. Three do not:

- **CR-0018-C1 — `download_rev.py:149`, `published_products`**:
  `except Exception: return None`. The PA-0027 sweep did not list it
  (it existed at `4683e3c^:145`; the sweep's `download_rev.py:113-126`
  entry is `_raster_valid_fraction`, BUG-0052). The caller
  (`download_rev.py:375-378`) prints "product listing unreachable - will
  try jobs without a pre-flight check", so the outcome is a visible
  unknown that falls back to the authoritative path (the job itself).
  But the printed message omits the exception type, which PA-0027's
  visible-unknown clause requires, and a programming error in the
  listing parser is indistinguishable from "unreachable". Candidate
  severity LOW.
- **CR-0018-C2 — `download_tcc_nlcd.py:338` and `download_treemap.py:263`,
  `fetch_tile`** (identical code, one candidate): bounded retry that raises
  `RuntimeError` on exhaustion, so it does fail closed. It departs from
  PA-0027's retry clause: it catches `Exception` rather than the
  transient types, and it logs nothing on each retry. The sweep classed
  both as "re-raise". A programming error is retried `retries` times with
  back-off before surfacing, without its traceback. Candidate severity LOW.

The lead decides whether each becomes a BUG (next free ids) and whether
C2 is one BUG or two. Whatever is decided, the entry leaves
`EXPECTED_UNCLASSIFIED` in the change that files or fixes it.

Also recorded, no new candidate: the three `KNOWN_OPEN` sites are
BUG-0013's (`download_rev.py:222,238` `download_one`, `ebird.py:106`
`main`; the sweep cited them as `:218,:234` before `4683e3c`).

### 5. Known limits (not detected; recorded, not in scope)
- A broad type reached through an alias (`E = Exception; except E:`) or a
  user-defined base class. None in the file set today: every handler
  type expression in the 61 scanned files was listed from the AST; apart
  from `Exception`/`BaseException` each is a builtin narrow type, a
  library type, or a project subclass of `Exception`
  (`AcceptanceError`, `ConfigError`, `GuardError`, `Missing`,
  `MissingDataError`, `MissingInput`, `ReplayError`), none an alias of a
  broad type.
- Narrow handlers that skip (`except OSError: continue`). PA-0027 is
  about broad handlers; narrow skips are governed by its "printed with
  what was skipped" clause, which is not mechanically checkable.
- Whether an allowlisted handler's *caller* treats its fail-closed value
  correctly (e.g. a probe returning `False` read as "skip"). The digest
  pins the handler, not the caller. Review only.
- `return`/`break`/`continue` inside `finally` (also swallows an in-flight
  exception). Not in PA-0027's text; tracked as a follow-up question.

## Impact
- Test-only. No production file, data file or schema changes. Nothing
  writes to `data/`.
- Any future change adding a broad handler that does not re-raise, or
  editing a classified one, now fails `python -m unittest
  tests.test_pa0027_lint` and must add or update an entry, which is a
  review item. That is the intended friction.
- Imports `check_partition.guard_first` (numpy/pandas import, ~0.3 s),
  as `tests/test_shared_constants.py` already does.

## Risk
LOW. Test-only change. Failure modes and mitigations:
- *False assurance*: an allowlist entry wrongly classifies a real defect
  as conforming. Mitigation: every entry is carried over from the PA-0027
  sweep with its sweep line cited, and two reviewers re-derive the
  classification from the code (Test plan T6).
- *Rule too narrow*: a defect shape the AST rule accepts (§5). Accepted
  risk, listed.
- *Churn*: digest pins fail on harmless edits (e.g. a message tweak).
  Accepted: re-review of an edited broad handler is the point of the PA.
