# CR-0025: `analyze_grouse.py` leaves no stale region outputs on a skip and exits non-zero

**Status: DRAFT v1, 2026-09-30 — awaiting independent review (CLAUDE.md §1.2). Nothing has been implemented.** Review log: `CR-0025-review-log.md`, to be created by the first reviewer.

## Scope
On any per-region skip, remove that region's previous outputs and make the run exit non-zero naming the skipped regions; write the two CSVs before the diagnostic map (BUG-0081; PA-0038).

## Why now
BUG-0081: five designed `return None` paths leave the previous run's `evaluated_sightings_{R}.csv` and `envelope_metrics_{R}.csv` in place, the run exits 0, and `prepare_training_data.py` / `generate_negatives.py` digest the stale files as current. Same outcome class as BUG-0049 (fixed in `generate_negatives.py` by CR-0012). It touches several functions and the CLI's exit status, so it is a CR rather than a set of trivial fixes.

## The change
### 1. Root cause
As BUG-0081 §5: outputs are written only after every stage completes, and a designed skip returns into a loop that continues and exits 0 without removing or marking the unit's previous outputs.

### 2. Code (normative)
- A helper `remove_region_outputs(region)` deletes, if present, `evaluated_sightings_{R}.csv`, `envelope_metrics_{R}.csv`, `nonveg_flagged_{R}.csv` and `availability_sample_{R}.csv` (all `PATH_TEMPLATES` entries) and prints each removal.
- Every skip path in `analyze_region` (`:251`, `:758`, `:786`; and `:882` for the envelope table only) calls it before returning; the `:882` path (all records non-vegetated) still writes `evaluated_sightings_{R}.csv` and `nonveg_flagged_{R}.csv` (they are complete) and removes only `envelope_metrics_{R}.csv` and the availability sample.
- The two CSV writes (`:1099-1100`) move ahead of the map block (`:1094-1097`), so a plotting failure cannot lose them; the map keeps its own `try` (BUG-0069 handlers) as today.
- `__main__`: after the summary, `raise SystemExit(1)` if any region was skipped, listing them; the summary line already prints "skipped".
- Consumers unchanged: a missing `evaluated_sightings_{R}.csv` already makes `prepare_training_data.py` raise `MissingDataError` (fail closed).

### 3. Acceptance
None (no split-file change). A unit test on a fixture tree: a region with a missing raster leaves no output files for it after the run and the process exit code is 1; the other regions' files are written; the `:882` path writes the sightings file and not the metrics file.

## Impact
- Behaviour on a healthy tree is unchanged (same files, same content, exit 0).
- A skip now removes stale files and fails the run; a wrapper script that ignored the exit status will notice.

## One change per CR (CR-0011 A5)
Pipeline code only; no data or acceptance change.

## Risk: LOW
| risk | mitigation |
|---|---|
| Removing outputs a user wanted to keep across a partial run | They are regenerated by a full run; the removal is printed; the alternative (stale files digested as current) is the defect |
| The exit-code change breaks an automation | None in the tree calls `analyze_grouse.py`; documented in CHANGELOG |
